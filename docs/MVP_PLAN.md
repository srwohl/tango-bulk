# Stock-cppTango bulk-stream MVP plan

This plan implements [DESIGN.md](DESIGN.md) as out-of-tree client/server extension libraries. Work
that modifies cppTango internals is explicitly out of scope. Hardware validation and library
extraction begin concurrently because transport results may influence internal batching and engine
configuration.

## Locked decisions

- Build and run against an installed, unmodified cppTango.
- Use explicit `BulkPublisher`/`BulkSubscriber` APIs.
- Use ordinary device `BulkOpen`, `BulkRenew`, and `BulkClose` commands for coordination.
- Make every UCX frame self-contained; no Tango ZMQ per-frame descriptor.
- Use expiring server-side session leases for crash cleanup.
- Start with active-message rendezvous and one direct consumer.
- Keep user callbacks off the UCX engine thread.
- Make bulk-only the performance path; use a separate Tango preview for legacy visibility.

## Parallel workstreams

### H — hardware evidence

Run the existing Tango-free spike on target RDMA systems while the reusable core is extracted.
Measure AM rendezvous first, then RMA where useful. Results are committed as reproducible command
lines, machine/NIC/UCX configuration, raw outputs, and a short conclusion in
[THROUGHPUT.md](THROUGHPUT.md).

### L — extension library

Build the protocol, ownership, lifecycle, engines, Tango adapter, and public APIs outside cppTango.
Do not copy the in-tree integration merely to preserve sunk work; preserve only validated contracts.

## Milestones

### M0 — freeze the fork prototype and establish the extension repository

- Record the source revision and files from which behavior may be extracted.
- Create an independent build whose only Tango input is an installed package.
- Add core, UCX, Tango-adapter, tests, examples, and benchmark targets.
- Ensure no include path points into a cppTango source or build tree.
- Preserve applicable LGPL notices and audit copied code before the first release.

Exit: an empty server/client extension and test executable configure against stock cppTango and UCX.

### M1 — hardware baseline and protocol core

Hardware track:

- run 1, 2, 4, and 8 MiB frames over one target 100 GbE link;
- sweep ring/credit depths and record NUMA/CPU affinity;
- measure AM throughput, CPU, latency, and drops;
- run two-rail tests when hardware is available;
- compare RMA/flush batching only after the AM baseline is trustworthy.

Library track:

- define versioned `Open`, `Renew`, `Close`, frame-header, credit, probe, and geometry messages;
- remove legacy `bulk_topic` and `BulkFrameDescriptor` fields;
- implement bounded decoding and explicit resource validation;
- define `FrameMetadata` independently of Tango IDL/CDR types.

Exit: protocol round trips and malformed-input tests pass; hardware results identify the MVP transport
or explicitly document the remaining gate.

### M2 — ownership-safe standalone UCX vertical slice

- Extract registered producer/consumer rings and move-only producer leases.
- Implement one dedicated submit+progress engine per worker/rail with bounded queues.
- Send one self-contained raw frame from a producer lease to a final receive slot.
- Return credit when the last `FrameView` releases the slot.
- Preserve header and payload lifetime through nonblocking UCX operations.
- Prove ring wraparound, retained views, out-of-order completion, and credit exhaustion.
- Dispatch callbacks outside the UCX engine; provide explicit `poll()` for deterministic tests.

Exit: zero payload-sized application copies on the eligible path, verified by pointer/registration
instrumentation and lifetime tests; no Tango process is required for this milestone.

### M3 — session lifecycle and fault containment

- Implement unpredictable session identifiers and negotiated TTL/renew interval.
- Add probe-before-ready and arm-before-send geometry interlocks.
- Implement `BulkRenew` state exchange and idempotent `BulkClose`.
- Expire crashed/unrenewed clients independent of frame traffic.
- On expiry: stop submission, close endpoint, release all per-session source leases, and update counters.
- Handle malformed renewals, late renewals, close races, server restart, and client restart.
- Bound pinned memory, queue capacity, sessions, frame size, and depth.

Exit: killing a client cannot exhaust producer slots beyond the configured lease deadline; recovery
does not require restarting the device server.

### M4 — stock Tango server/client adapter

Server:

- provide reusable ordinary-command implementations/codecs for `BulkOpen`, `BulkRenew`, and
  `BulkClose`;
- provide a small registration helper suitable for a normal device class;
- expose `PublisherSnapshot` through a separate low-rate preview attribute example;
- source `FrameMetadata` directly from device state and the acquired lease;
- never construct `AttributeValue_5` or call `push_change_event()` on the bulk-only path.

Client:

- accept a stock `Tango::DeviceProxy` and logical stream name;
- negotiate, renew, close, and reopen sessions;
- expose typed state/error callbacks separately from frame callbacks;
- treat Tango connection errors as recovery hints, not supplier cleanup authority.

Exit: an example device and client use only installed cppTango public headers plus extension headers;
the cppTango source tree is absent from their build environment.

### M5 — external acceptance and observability

Implement [M5_TEST_GUIDE.md](M5_TEST_GUIDE.md):

- clean installed-package build against a supported stock cppTango release;
- end-to-end data/metadata correctness;
- source and destination lifetime safety;
- session crash expiry and reconnect;
- backpressure/drop counters;
- geometry changes;
- performance on target hardware;
- proof that bulk-only operation emits no full-rate Tango event.

Expose counters for frames submitted/completed/dropped, credits outstanding, queue depth/high-water,
leases retained, sessions opened/expired/closed, geometry changes, malformed messages, memory kind,
transport, and staged/direct route where UCX can report it.

Exit: the acceptance matrix passes and a target-hardware report meets the agreed throughput/CPU
budget or records a clear no-go decision.

### M6 — relay and optional language bindings

- Implement a relay that consumes the detector stream once and publishes to multiple downstream
  clients with independent policies.
- Measure relay copy/registration strategy and total link capacity.
- Add an optional Python client that copies into Python-owned memory; do not promise zero-copy
  lifetime semantics through NumPy until they are independently designed.

M6 is post-MVP unless the first deployment requires more than one consumer.

## Work explicitly removed from the plan

- cppTango CMake/configuration changes;
- cppTango-local bulk IDL generation;
- DServer command additions;
- `DeviceProxy::subscribe_event()` overloads;
- `EventData::bulk_frame`;
- `ZmqEventSupplier`/`ZmqEventConsumer` hooks;
- authority cutover and legacy-topic subscription manipulation;
- cross-platform dummy APIs when UCX is unavailable;
- wire compatibility with the undeployed in-tree prototype.

## Release gate

The MVP is releasable only when all are true:

1. Stock cppTango packages can be substituted without rebuilding the extension.
2. Client crash cleanup is bounded by the negotiated session lease.
3. The bulk-only producer path performs no Tango CDR/event payload marshalling.
4. The eligible producer-to-consumer path has no payload-sized application copy.
5. Engine progress is independent of Tango event and user callback pacing.
6. Target-hardware measurements meet the agreed single-consumer objective.
7. The limitations—Linux/UCX, one direct consumer, explicit drops, retained-view credits, and no
   transparent event fallback—are documented as API properties.
