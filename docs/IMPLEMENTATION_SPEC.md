# tango-bulk implementation specification

Status: **normative contract, pre-implementation**

This document exists so that implementation can begin without inventing decisions while coding.
Where [DESIGN.md](DESIGN.md) says *what* and [MVP_PLAN.md](MVP_PLAN.md) says *in what order*, this
document says *exactly what to type*. It supersedes those two documents on any point of detail; it
does not reopen their architecture.

Requirement keywords **MUST**, **MUST NOT**, **SHOULD**, and **MAY** are used in the RFC 2119 sense.

Companion evidence: [FINDINGS.md](FINDINGS.md) (correctness/registration), [THROUGHPUT.md](THROUGHPUT.md)
(measured transport behaviour), [M5_TEST_GUIDE.md](M5_TEST_GUIDE.md) (acceptance matrix).

## 0. Settled choices

[DESIGN.md](DESIGN.md) §14 left five policy choices open. They are settled here so no implementation
decision is deferred into code review.

| Open choice | Decision | Rationale |
|---|---|---|
| Command prefix | `BulkOpen` / `BulkRenew` / `BulkClose`, unprefixed by default; a `CommandNames` struct allows a per-device prefix | Unprefixed names are discoverable and match the docs already written; the override exists for devices with a name collision, not as the normal path |
| Default lease timings | TTL 10 000 ms, renew interval 3 333 ms (TTL/3), both negotiated per session | Three renewal attempts fit inside one TTL, so a single lost Tango command never expires a healthy session |
| Callback executor default | One library-owned dispatch thread per subscriber; `DeliveryMode::Pull` + `read_for()` for caller-owned reads | Structurally guarantees §5's "callbacks never run on the engine thread" while keeping delivery ownership immutable per subscription |
| Wire codec | Hand-written fixed-offset little-endian encode/decode, with a `header_bytes` trailing-extension rule | Already validated in the prototype ([bulk_wire.h](../../src/include/tango/internal/ucx/bulk_wire.h)); adds no dependency, decodes in a few ns inside an AM callback, and keeps the protocol independent of Tango IDL and of any third-party schema compiler |
| Relay in MVP? | **No.** Relay is M6, post-MVP | The MVP objective is one line-rate consumer; fan-out is a capacity problem, not a semantics problem, and shipping it early would not be exercised |

Additional project-level choices settled here:

| Choice | Decision |
|---|---|
| Language standard | C++17 (matches cppTango's `cxx_std_17`); C++20 MAY be enabled downstream but MUST NOT be required |
| Build system | CMake ≥ 3.18, matching cppTango's floor |
| License | LGPL-3.0-or-later, with `SPDX-FileCopyrightText` headers preserved on every extracted file |
| Namespace | `TangoBulk` |
| Include root | `<tango-bulk/…>` |
| Test framework | Catch2 ≥ 3.1.1 |
| UCX floor | 1.21.0 |
| Platform | Linux only. The build MUST fail configuration on other platforms rather than emit stub APIs |

### 1.1 Dependency rules (enforced, not advisory)

| Target | May include | MUST NOT include |
|---|---|---|
| `tango-bulk-core` | libstdc++ only | `ucp/*`, `tango/*` |
| `tango-bulk-ucx` | core, `ucp/*` | `tango/*` |
| `tango-bulk-tango` | core, `tango/*` | `ucp/*` |
| `tango-bulk` (umbrella) | all three | — |

`tango-bulk-tango` MUST NOT include `ucp/api/ucp.h`. The Tango adapter deals in encoded byte
vectors and opaque handles, so a device server that links the adapter never inherits UCX headers.

A CI step MUST `grep` each target's translation units for forbidden includes and fail the build on
violation. This is cheap and it is the only thing that keeps the layering real.

### 1.2 Tango coupling rules

The build MUST locate cppTango through its installed CMake package only:

```cmake
find_package(Tango REQUIRED)   # provides Tango::Tango
```

The configure step MUST fail if `Tango_INCLUDE_DIRS` resolves inside a cppTango *source or build*
tree. That check is the mechanical form of the M0 exit criterion, and it is the difference between
"out of tree" as an intention and as a property.

Error discipline: the **control path** (construction, `open()`, `install_bulk_commands`) throws
`BulkException`. The **data path** (`try_acquire`, `publish`, credit return, AM callbacks) MUST NOT
throw and MUST NOT allocate; it returns status enums and bumps counters.

### 2.2 `include/tango-bulk/frame.h`

```cpp
namespace TangoBulk {

inline constexpr std::size_t k_max_rank = 4;

enum class ElementType : std::uint32_t
{
    Unknown = 0, UInt8 = 1, Int8 = 2, UInt16 = 3, Int16 = 4,
    UInt32  = 5, Int32 = 6, UInt64 = 7, Int64 = 8,
    Float32 = 9, Float64 = 10, Byte = 11,   // Byte = opaque, element_size 1
};

enum class MemoryKind : std::uint32_t { Host = 0, Cuda = 1, Rocm = 2 };
enum class Endian     : std::uint32_t { Little = 0, Big = 1 };

std::uint32_t element_size_of(ElementType) noexcept;   // 0 for Unknown

// Producer-supplied description of one frame. Populated from device state, never
// derived from AttributeValue_5 or any CDR object.
struct FrameMetadata
{
    ElementType element_type{ElementType::Unknown};
    std::uint32_t element_size{0};        // 0 => infer via element_size_of()
    std::uint32_t rank{0};                // 0..k_max_rank
    std::array<std::uint64_t, k_max_rank> shape{};
    std::array<std::uint64_t, k_max_rank> strides{};   // bytes; 0 => infer C-contiguous
    std::uint64_t payload_bytes{0};       // 0 => infer from shape x element_size
    std::uint64_t timestamp_ns{0};        // acquisition time, CLOCK_REALTIME; 0 => stamp at publish
    std::uint64_t event_counter{0};       // producer-defined; opaque to the protocol
    std::uint32_t quality{0};             // producer-defined
    MemoryKind memory_kind{MemoryKind::Host};
    Endian endian{Endian::Little};        // byte order of payload *elements*

    // Rejects rank > k_max_rank, zero/oversize element_size, stride/shape
    // products that overflow or exceed payload_bytes, and Unknown with rank > 0.
    Status validate(std::uint64_t max_frame_bytes) const noexcept;
};

// Read-only, reference-counted view of one delivered frame. Every copy keeps the
// receive slot alive; the credit for that slot is withheld until the last copy is
// destroyed. Applications needing unbounded ownership MUST copy and release.
class FrameView
{
  public:
    FrameView() noexcept = default;
    FrameView(const FrameView &) noexcept = default;
    FrameView(FrameView &&) noexcept = default;
    FrameView &operator=(const FrameView &) noexcept = default;
    FrameView &operator=(FrameView &&) noexcept = default;
    ~FrameView() = default;

    explicit operator bool() const noexcept;

    const std::byte *data() const noexcept;
    std::size_t      size() const noexcept;
    const std::byte *begin() const noexcept;
    const std::byte *end() const noexcept;

    ElementType   element_type() const noexcept;
    std::uint32_t element_size() const noexcept;
    std::uint32_t rank() const noexcept;
    const std::array<std::uint64_t, k_max_rank> &shape() const noexcept;
    const std::array<std::uint64_t, k_max_rank> &strides() const noexcept;

    std::uint64_t sequence() const noexcept;
    std::uint64_t event_counter() const noexcept;
    std::uint64_t timestamp_ns() const noexcept;
    std::uint64_t dropped_before() const noexcept;   // cumulative, publisher-side
    std::uint32_t quality() const noexcept;
    std::uint32_t generation() const noexcept;       // geometry epoch
    MemoryKind    memory_kind() const noexcept;
    Endian        endian() const noexcept;

    long use_count() const noexcept;                 // diagnostics/tests only
    void reset() noexcept;                           // release early; returns the credit

    struct Fields { /* POD: shape, strides, sequence, timestamps, type, ... */ };

    // A view over caller-owned memory that references no receive slot. Holds a
    // real lease over a discarding sink, so operator bool, use_count() and
    // reset() behave exactly as they do for a delivered frame. `fields` is
    // copied; `data` is never dereferenced and may be a device pointer.
    static FrameView detached(std::shared_ptr<const void> owner,
                              const std::byte *data,
                              const Fields &fields);

  private:
    friend class detail::ReceiveSlotLease;
    FrameView(std::shared_ptr<detail::ReceiveSlotLease>, const std::byte *,
              const Fields *) noexcept;
    std::shared_ptr<detail::ReceiveSlotLease> lease_;
    const std::byte *data_{nullptr};
    const Fields *fields_{nullptr};
};

} // namespace TangoBulk
```

`Fields` is public. The receive path populates one, and an application building a synthetic frame
populates one; hiding it would buy nothing and cost a friend declaration per implementation file.

`detached()` exists because the receive path's constructor is private, which left an application
unable to construct a `FrameView` at all — and therefore unable to unit-test anything written
against `FrameCallback`, which is `void(FrameView)` and so is most of what an application writes.
Testing those against a live publisher is an integration test, not a unit test, and it does not run
where there is no fabric. A synthetic view is deliberately indistinguishable from a delivered one
in every observable, because a fixture that behaves differently from the thing it stands in for
cannot answer the question worth asking of this API: *does this code hold the view longer than it
should?*

`FrameView` is deliberately Tango-free: no `EventData`, no `DeviceAttribute`, no `AttributeValue_5`.
That is the removal of the Tango dependency called for in the extraction map (§8).

The `std::shared_ptr` control block is the credit interlock. `reset()` and destruction are the only
ways a credit returns; there is no explicit `release_credit()` call for an application to forget.

### 2.3 `include/tango-bulk/publisher.h`

```cpp
namespace TangoBulk {

enum class DropPolicy : std::uint32_t
{
    DropNewest = 0,   // reject the frame being published (producer default)
    DropOldest = 1,   // delivery queue only; illegal on the producer ring
};

enum class FanoutMode : std::uint32_t
{
    BestEffort = 0, // a lagging session misses frames without stopping peers
    AllActive = 1,  // retain and retry until every armed session has credit
};

struct PublisherConfig
{
    std::string   stream_name;                  // 1..64 bytes, [A-Za-z0-9_.-]
    std::uint64_t max_frame_bytes{8ull << 20};
    std::uint32_t ring_depth{32};
    std::uint32_t credit_window{16};            // MUST be <= ring_depth
    std::uint32_t max_sessions{4};
    FanoutMode    fanout_mode{FanoutMode::BestEffort};
    std::uint32_t publish_queue_depth{256};
    std::uint32_t lease_ttl_ms{10'000};
    std::uint32_t renew_interval_ms{3'333};
    std::uint64_t pinned_memory_limit_bytes{1ull << 30};
    DropPolicy    drop_policy{DropPolicy::DropNewest};
    std::string   ucx_tls;                      // empty => let UCX choose; tests pin
    int           engine_cpu_affinity{-1};      // -1 => unpinned
    bool          pad_slot_stride{true};        // see 6.2

    Status validate() const noexcept;
};

// Registered producer ring. One ucp_mem_map registration covers the whole ring;
// slots are offsets into it, so the MR count is 1 regardless of depth.
class BulkSource
{
  public:
    // Move-only handle to one producer slot. Publishing consumes the lease.
    class Lease
    {
      public:
        Lease() noexcept = default;
        Lease(Lease &&) noexcept;
        Lease &operator=(Lease &&) noexcept;
        Lease(const Lease &) = delete;
        Lease &operator=(const Lease &) = delete;
        ~Lease();                                  // un-published lease returns the slot

        explicit operator bool() const noexcept;
        void       *data() const noexcept;
        std::size_t capacity() const noexcept;
        std::size_t index() const noexcept;
        MemoryKind  memory_kind() const noexcept;
        void        reset() noexcept;

      private:
        friend class BulkSource;
        friend class BulkPublisher;
        struct Impl;
        std::unique_ptr<Impl> impl_;
    };

    // Non-blocking by design: an acquisition thread MUST be able to drop rather
    // than wait while slots are retained by a slow or dead consumer.
    Lease try_acquire() noexcept;

    std::size_t slot_count() const noexcept;
    std::size_t slot_bytes() const noexcept;   // usable payload capacity per slot
    std::size_t slot_stride() const noexcept;  // >= slot_bytes; see 6.2
    std::size_t retained() const noexcept;     // slots currently uncredited

  private:
    friend class BulkPublisher;
    struct Impl;
    std::unique_ptr<Impl> impl_;
};

enum class PublishResult : std::uint32_t
{
    Accepted      = 0,
    NoSession     = 1,   // no armed session; frame dropped, counted
    QueueFull     = 2,   // publish queue full; lease returned to caller
    CreditStalled = 3,   // credit window closed; frame dropped, counted
    BadMetadata   = 4,
    Shutdown      = 5,
    WouldBlock    = 6,   // AllActive session lacks credit; lease stays with caller
};

class BulkPublisher
{
  public:
    explicit BulkPublisher(PublisherConfig config);   // throws BulkException
    ~BulkPublisher();
    BulkPublisher(BulkPublisher &&) noexcept;
    BulkPublisher &operator=(BulkPublisher &&) noexcept;
    BulkPublisher(const BulkPublisher &) = delete;
    BulkPublisher &operator=(const BulkPublisher &) = delete;

    BulkSource &source() noexcept;

    // Consumes the lease on Accepted; returns it to the caller (via `lease`
    // remaining engaged) on QueueFull. Never blocks, never throws, never allocates.
    PublishResult publish(BulkSource::Lease &&lease, const FrameMetadata &meta) noexcept;

    // Re-declare geometry. Opens a new epoch; see 4.3 for the interlock.
    Status declare_geometry(const FrameMetadata &prototype,
                            std::uint64_t max_frame_bytes,
                            std::uint32_t ring_depth);

    std::uint32_t generation() const noexcept;
    std::size_t   session_count() const noexcept;
    PublisherCounters counters() const noexcept;

    // Coordination entry points. The Tango adapter calls these; they are public
    // so a non-Tango transport (tests, a future control plane) can drive them.
    std::vector<std::byte> handle_coordination(const std::byte *data,
                                               std::size_t size) noexcept;

  private:
    struct Impl;
    std::unique_ptr<Impl> impl_;
};

} // namespace TangoBulk
```

`handle_coordination` is the seam that keeps Tango out of the core: it takes encoded bytes and
returns encoded bytes. `src/tango/commands.cpp` is a thin `DevVarCharArray` adapter over it, and the
unit tests drive the entire session lifecycle through it with no Tango process at all.

## 3. Exact wire protocol

Two planes, deliberately different in shape:

- **Coordination plane** — request/reply, over ordinary Tango commands, `DevVarCharArray` in both
  directions. Low rate, allowed to allocate, allowed to be verbose.
- **Data plane** — one-way messages over UCX active messages. Per-frame rate, fixed size, decoded
  inside an AM callback with no allocation.

### 3.0 Universal conventions

1. **Endianness.** Every multi-byte integer field in every message is **little-endian**, regardless
   of host. Encoders and decoders use explicit byte-at-a-time `put16/put32/put64` and `get16/get32/get64`
   helpers. A native struct **MUST NOT** be `memcpy`'d onto the wire. (`Endian endian` inside a frame
   header describes the *payload elements*, not the header — the header is always little-endian.)
2. **Padding.** Every field has an explicit offset. Every message length is a multiple of 8. Reserved
   bytes **MUST** be written as zero and **MUST** be ignored on receipt.
3. **Strings.** `u16 length` followed by exactly `length` bytes of UTF-8, no NUL terminator, no
   embedded NUL. Bounded per field (§3.9).
4. **Blobs.** `u32 length` followed by exactly `length` bytes. Bounded per field.
5. **Variable-length fields** appear only after all fixed fields, in the order declared, and only in
   coordination messages. Data-plane messages are fixed-size, always.
6. **Signedness.** No signed integers appear on the wire.
7. **Floating point.** None appears on the wire. Timestamps are `u64` nanoseconds.
8. **Truncation is an error.** A message shorter than its declared fixed part is `MalformedMessage`;
   a decoder **MUST NOT** read past the supplied length under any circumstance, including when
   `header_bytes` claims a larger value than was delivered.

### 3.1 Versioning rules

Both planes carry `version_major` (`u8`), `version_minor` (`u8`), and `header_bytes` (`u16`).

- **`version_major`** — incompatible change. A receiver **MUST** reject any message whose
  `version_major` differs from a value it supports, with `Status::UnsupportedVersion`. Majors are
  never silently downgraded on the data plane.
- **`version_minor`** — additive change only. New fields are appended in the reserved tail; existing
  offsets never move; existing semantics never change.
- **`header_bytes`** — the encoder's fixed-part size. A receiver reads
  `min(header_bytes, sizeof(its own known layout))` bytes and ignores any trailing excess. If
  `header_bytes` is **less than the minimum defined for that (major, msg_type)**, the message is
  malformed. This is what makes minor-version forward compatibility mechanical rather than aspirational.
- **Negotiation.** Only `Open` negotiates. The client offers `[version_min, version_max]`; the server
  selects the highest major it supports within that range and returns it in `OpenReply.version_selected`.
  If the ranges do not intersect, the server replies `Error` with `UnsupportedVersion` and does not
  allocate anything.
- **Data plane follows coordination.** Every data-plane message on a session uses exactly the major
  selected in that session's `OpenReply`. A data-plane message with a different major is dropped and
  counted (`frames_dropped_bad_header`), never negotiated mid-session.

This document defines **major 1, minor 0**.

### 3.2 Session and stream identifiers

| Identifier | Width | Plane | Representation |
|---|---|---|---|
| `session_id` | 128 bit | coordination | 16 opaque octets, no endianness (byte string) |
| `stream_id` | 64 bit | data | `u64`, little-endian like every other integer |
| `client_instance_id` | 128 bit | coordination | 16 opaque octets, chosen by the client |

Rules:

- `session_id` **MUST** be drawn from a cryptographic RNG (`getrandom(2)`; `std::random_device` is
  acceptable only if it is verified non-deterministic at startup). It **MUST NOT** be a counter, a
  hash of the client address, a PID, or a timestamp.
- `stream_id` is a *separate* 64-bit handle, also from the CSPRNG, issued in `OpenReply`. It exists
  because the data plane cannot afford 16 bytes of identity in a per-frame header, and because a
  128-bit value would push the frame header past a comfortable AM header size. It is valid only on
  the endpoint it was issued to.
- Both are unique among live sessions on a server instance and **MUST NOT** be reused within the
  lifetime of the publisher process, even after the session closes. Reuse is what makes a late frame
  from a dead session indistinguishable from a live one.
- Text form (logs, `BulkStreams`): lowercase hex. Logs **MUST** print only the first 8 hex characters
  followed by `…`. Full identifiers, UCX worker addresses, and memory keys **MUST NOT** be logged at
  any level below debug.

### 3.3 Coordination envelope

Every coordination message, in both directions, begins with this 32-byte envelope.

```text
offset  size  field              notes
------  ----  -----------------  --------------------------------------------------
     0     4  magic              0x4B4C4254  ("TBLK", little-endian u32)
     4     1  version_major      1
     5     1  version_minor      0
     6     2  header_bytes       32 for major 1
     8     2  msg_type           see table below
    10     2  flags              0 in major 1; reserved
    12     4  body_bytes         length of everything after this envelope
    16     8  correlation_id     echoed unchanged in the reply; client-chosen
    24     8  reserved           0
------  ----  -----------------  --------------------------------------------------
   total 32
```

| `msg_type` | Message | Direction |
|---|---|---|
| `0x0001` | `Open` | client → server |
| `0x0002` | `OpenReply` | server → client |
| `0x0003` | `Renew` | client → server |
| `0x0004` | `RenewReply` | server → client |
| `0x0005` | `Close` | client → server |
| `0x0006` | `CloseReply` | server → client |
| `0x0008` | `RenewReply` | server → client |
| `0x00FF` | `Error` | server → client |

A server **MAY** reply `Error` to any request. A client **MUST** accept `Error` in place of any
expected reply type.

### 3.4 `GeometryBlock` (96 bytes, embedded)

Reused verbatim by `OpenReply`, `RenewReply`, `RenewReply`, and the data-plane `Geometry` message.
One layout, one validator, one set of bounds checks.

```text
offset  size  field              notes
------  ----  -----------------  --------------------------------------------------
     0     4  generation         geometry epoch; starts at 1, increments, never wraps
     4     4  element_type       ElementType
     8     4  element_size       bytes per element, 1..256
    12     4  rank               0..4
    16     8  max_frame_bytes    granted per-frame payload ceiling
    24     4  ring_depth         granted slot count
    28     4  credit_window      granted window width; <= ring_depth
    32    32  shape[4]           u64 each; entries >= rank MUST be 0
    64    32  strides[4]         u64 bytes each; entries >= rank MUST be 0
------  ----  -----------------  --------------------------------------------------
   total 96
```

Validation (`src/core/geometry.cpp`), applied on every receipt:

- `rank <= 4`; `shape[i] == 0` and `strides[i] == 0` for all `i >= rank`.
- `element_size` in `1..256`; if `element_type != Unknown`, `element_size == element_size_of(element_type)`.
- `1 <= max_frame_bytes <= k_max_frame_bytes_hard_cap` (§6.1).
- `2 <= ring_depth <= 1024`; `1 <= credit_window <= ring_depth`.
- The product `shape[0] * … * shape[rank-1] * element_size` **MUST** be computed with overflow
  checking and **MUST** be `<= max_frame_bytes`.
- Each `strides[i]`, multiplied by `shape[i]`, **MUST** be computed with overflow checking and
  **MUST** be `<= max_frame_bytes`.
- `generation != 0`. Zero means "never armed" and is only legal as a *local* sentinel, never on the wire.

### 3.5 `Open` (msg_type 0x0001)

```text
offset  size  field                     notes
------  ----  ------------------------  -------------------------------------------
     0     1  version_min               lowest major the client accepts
     1     1  version_max               highest major the client accepts
     2     2  reserved                  0
     4     4  requested_caps            bitfield, see below
     8    16  client_instance_id        128-bit, client-chosen, stable across reopen
    24     8  requested_max_frame_bytes
    32     4  requested_ring_depth
    36     4  requested_credit_window
    40     4  requested_memory_kind     MemoryKind
    44     4  requested_transport       0 = any, 1 = AM rendezvous, 2 = RMA
    48     4  drop_policy               DropPolicy the client will apply locally
    52     4  reserved                  0
------  ----  ------------------------  -------------------------------------------
    56        stream_name               u16 length + UTF-8 bytes (1..64)
     …        client_ucx_address        u32 length + bytes (1..4096)
```

`requested_caps` bits (major 1): bit 0 `caps_credit_coalescing`, bit 1 `caps_geometry_rearm`,
bit 2 `caps_probe`. Unknown bits **MUST** be ignored, not rejected — that is what lets a minor
version add a capability without breaking an older server.

Server behaviour on `Open`:

1. Decode and validate. Any failure → `Error{MalformedMessage}`, nothing allocated.
2. Version intersect. No overlap → `Error{UnsupportedVersion}`.
3. Resolve `stream_name`. Unknown → `Error{UnknownStream}`.
4. Check `max_sessions`. Exceeded → `Error{TooManySessions}`.
5. Clamp `requested_*` **downward** to configured limits. A grant is never larger than requested and
   never larger than configured. Clamping is normal and is reported in the reply, not an error;
   exceeding a *hard cap* (§6.1) is `Error{FrameTooLarge}` / `Error{DepthTooLarge}`.
6. Check pinned-memory budget for `granted_max_frame_bytes * granted_ring_depth`. Over budget →
   `Error{ResourceExhausted}` **before** any `ucp_mem_map` call.
7. Allocate session, register the ring, create the endpoint to `client_ucx_address`, arm the lease,
   and reply.

### 3.6 `OpenReply` (msg_type 0x0002)

```text
offset  size  field                notes
------  ----  -------------------  ------------------------------------------------
     0     1  version_selected     the major in force for this session
     1     1  reserved             0
     2     2  status               Status; nonzero => remaining fields undefined
     4     4  granted_caps         subset of requested_caps
     8    16  session_id           128-bit, CSPRNG
    24     8  stream_id            64-bit data-plane handle, CSPRNG
    32     4  lease_ttl_ms
    36     4  renew_interval_ms
    40     4  transport_selected   1 = AM rendezvous, 2 = RMA
    44     4  reserved             0
    48     8  server_epoch_id      changes on server restart; see 4.4
------  ----  -------------------  ------------------------------------------------
    56    96  geometry             GeometryBlock (3.4)
------  ----  -------------------  ------------------------------------------------
   152        server_ucx_address   u32 length + bytes (1..4096)
```

`server_epoch_id` is a CSPRNG value chosen once per publisher process start. A client that sees a
different `server_epoch_id` on reopen knows the server restarted rather than merely dropped the
session, and **MUST** discard all cached geometry and sequence state.

### 3.7 `Renew` / `RenewReply` (msg_type 0x0003 / 0x0004)

`Renew` body — 40 bytes, fixed, no variable part:

```text
offset  size  field                     notes
------  ----  ------------------------  -------------------------------------------
     0    16  session_id
    16     8  client_frames_delivered   cumulative; diagnostics only
    24     8  client_credits_returned   cumulative; diagnostics only
    32     4  client_state              SubscriberState
    36     4  reserved                  0
```

`RenewReply` body — 128 bytes, fixed:

```text
offset  size  field                notes
------  ----  -------------------  ------------------------------------------------
     0    16  session_id           echoed
    16     2  status               Status
    18     2  reserved             0
    20     4  lease_ttl_ms         MAY change; client MUST adopt the new value
    24     4  renew_interval_ms    MAY change; client MUST adopt the new value
    28     4  server_state         server-side session state (4.2)
    32    96  geometry             GeometryBlock — always the CURRENT epoch
```

Renew rules:

- A `Renew` for an unknown or already-closed `session_id` → `RenewReply{UnknownSession}` (not `Error`),
  so a client can distinguish "you are gone, reopen" from "your message was garbage".
- A `Renew` arriving after expiry → `RenewReply{SessionExpired}`. The client **MUST NOT** treat this
  as recoverable for that session; it **MUST** open a new one. There is no resurrection.
- Renew carries the current `GeometryBlock` unconditionally. This is the *only* mandatory way a
  client learns about a geometry change, because the data-plane `Geometry` message may be lost or may
  race a reconnect (see §4.3).
- Rate limiting: more than `k_max_renewals_per_ttl` (§6.1) accepted renewals within one TTL window →
  `RenewReply{RenewTooFrequent}`. The lease is **not** shortened as a penalty; the reply is simply
  refused, and `renewals_rejected` is incremented.

### 3.8 `Close` / `CloseReply` / `Error`

`Close` body — 24 bytes:

```text
offset  size  field         notes
------  ----  ------------  -------------------------------------------------------
     0    16  session_id
    16     4  reason        0 = normal, 1 = client shutdown, 2 = client error
    20     4  reserved      0
```

`CloseReply` body — 24 bytes:

```text
offset  size  field                 notes
------  ----  --------------------  -----------------------------------------------
     0    16  session_id            echoed
    16     2  status                Ok, or UnknownSession for an already-closed id
    18     2  reserved              0
    20     4  frames_credited_final  low 32 bits; diagnostics
```

`Close` is **idempotent**. A repeat `Close` for a session already closed returns
`CloseReply{UnknownSession}` and performs no work. It is never an `Error`, and it never throws on
the client side — a client tearing down after a fault must not be punished for closing twice.

`Error` body — 8 bytes fixed + message:

```text
offset  size  field       notes
------  ----  ----------  ---------------------------------------------------------
     0     2  status      Status, never Ok
     2     2  reserved    0
     4     4  reserved    0
------  ----  ----------  ---------------------------------------------------------
     8        message     u16 length + UTF-8 bytes (0..512), human-readable
```

### 3.9 Coordination bounds

| Quantity | Bound | On violation |
|---|---|---|
| Total coordination message | 65 536 bytes | `MalformedMessage` |
| `body_bytes` | 65 504 | `MalformedMessage` |
| `stream_name` | 1..64 bytes, `[A-Za-z0-9_.-]` only | `MalformedMessage` |
| `client_ucx_address` / `server_ucx_address` | 1..4096 bytes | `MalformedMessage` |
| `Error.message` | 0..512 bytes | truncate on encode; reject on decode |

A decoder **MUST** verify that the sum of the envelope, the fixed body, and every declared
variable-length field exactly equals the delivered length. Trailing unexplained bytes are
`MalformedMessage`, not "ignore the tail" — the trailing-extension rule applies to `header_bytes`
within the *fixed* part only, never to the variable tail.

### 3.10 Data-plane common prefix (16 bytes)

Every data-plane message begins with this prefix, so an AM callback can classify and version-check
before touching anything type-specific.

```text
offset  size  field           notes
------  ----  --------------  -----------------------------------------------------
     0     4  magic           0x314B4254  ("TBK1", little-endian u32)
     4     1  version_major   1
     5     1  version_minor   0
     6     2  header_bytes    total header size for this msg_type
     8     2  msg_type        see table
    10     2  flags           0 in major 1
    12     4  generation      geometry epoch this message belongs to
```

| `msg_type` | Message | AM id | Direction | Header bytes | Payload |
|---|---|---|---|---|---|
| `1` | `Frame` | 0 | publisher → subscriber | 160 | frame payload |
| `2` | `Credit` | 1 | subscriber → publisher | 32 | none |
| `3` | `Probe` | 2 | publisher → subscriber | 32 | none |
| `4` | `ProbeAck` | 3 | subscriber → publisher | 32 | none |
| `5` | `Geometry` | 4 | publisher → subscriber | 128 | none |
| `6` | `GeometryAck` | 5 | subscriber → publisher | 32 | none |

> **Deliberate change from the prototype.** [bulk_wire.h](../../src/include/tango/internal/ucx/bulk_wire.h)
> gave probe acks and credits the same AM id, which forced the `k_probe_seq = ~0ull` sentinel to stop a
> probe ack from sliding the credit window past a frame that was never sent. Separate AM ids for
> `Credit` and `ProbeAck` remove the sentinel and the class of bug it guards against. `k_probe_seq`
> **MUST NOT** appear in the new protocol.

The engine **MUST** query `ucp_worker_attr_t.max_am_header` at startup and fail construction with
`Status::Internal` if it is below 160. Discovering that limit at the first frame is not acceptable.

### 3.11 `Frame` header (160 bytes)

Carried as the UCX **AM header**. The frame payload is the AM data, sent from the registered producer
slot with no intermediate copy.

```text
offset  size  field            notes
------  ----  ---------------  ----------------------------------------------------
     0    16  common prefix    3.10; msg_type = 1, header_bytes = 160
    16     8  stream_id
    24     8  sequence         monotonic within a session, from 0, never wraps
    32     8  payload_bytes    == the AM data length; receiver MUST cross-check
    40     8  timestamp_ns     acquisition time, CLOCK_REALTIME
    48     8  event_counter    producer-defined, opaque
    56     8  dropped_before   cumulative frames dropped before this one
    64     4  element_type
    68     4  element_size
    72     4  rank
    76     4  quality
    80     4  memory_kind
    84     4  endian           byte order of payload ELEMENTS
    88    32  shape[4]
   120    32  strides[4]
   152     8  reserved         0
------  ----  ---------------  ----------------------------------------------------
   total 160
```

Receiver validation, in this order, inside the AM callback — every failure drops the frame, bumps a
counter, and returns `UCS_OK` (never aborts the worker):

1. `magic`, `version_major`, `header_bytes >= 160`, `msg_type == 1` → else `frames_dropped_bad_header`.
2. `stream_id` matches this session → else `frames_dropped_bad_header`.
3. `payload_bytes == am_data_length` → else `frames_dropped_bad_header`.
4. `payload_bytes <= granted max_frame_bytes` → else `frames_dropped_oversize`.
5. `generation` equals the armed epoch, or the epoch still draining (§4.3) → else
   `frames_dropped_stale_epoch`.
6. `sequence` within `[window_base, window_base + credit_window)` and not already occupied → else
   `frames_dropped_duplicate_seq`.
7. `GeometryBlock`-equivalent field checks from §3.4 on `rank`, `element_size`, `shape`, `strides`.

Only after all seven does the receiver commit the slot. The slot index is `sequence % ring_depth`.

### 3.12 `Credit` (32 bytes)

```text
offset  size  field           notes
------  ----  --------------  -----------------------------------------------------
     0    16  common prefix   msg_type = 2, header_bytes = 32
    16     8  stream_id
    24     8  ack_sequence    CUMULATIVE: every seq <= ack_sequence is released
```

Credit is **cumulative**, not per-sequence. `ack_sequence` is the highest sequence for which this
subscriber, *and every sequence below it*, has released its slot.

Consequences, all of them wanted:

- **Idempotent.** A duplicate or reordered `Credit` with a lower `ack_sequence` is ignored; the
  window base only ever moves forward.
- **Loss-tolerant.** A dropped credit message is repaired by the next one. No retransmit logic.
- **Coalescing is free.** The subscriber's engine sends at most one `Credit` per progress iteration
  regardless of how many views were released, which is what `credit_messages_sent` measures.
- **Out-of-order release is handled on the subscriber side.** Views released out of order are
  recorded in a bitmap; `ack_sequence` advances only across the contiguous released prefix. This is
  the same invariant the prototype's `SeqWindow::credited_ahead` set enforced, moved to the side that
  actually knows about it and expressed as a fixed-size bitmap rather than a `std::set` — no
  allocation on the data path.

Publisher on receipt: for every sequence in `(window_base, ack_sequence]`, release the corresponding
producer lease and increment `frames_credited`. Then `window_base = ack_sequence`. An `ack_sequence`
above the highest submitted sequence is a protocol violation → drop, `malformed_messages++`, and
**do not** advance the window. That check is what stops a buggy or hostile subscriber from talking
the publisher into recycling a slot the NIC is still reading.

### 3.13 `Probe` (32 bytes) / `ProbeAck` (32 bytes)

```text
Probe                                   ProbeAck
offset size field                       offset size field
  0     16  common prefix (msg_type 3)     0     16  common prefix (msg_type 4)
 16      8  stream_id                     16      8  stream_id
 24      8  probe_token                   24      8  probe_token   (echoed exactly)
```

`probe_token` is a fresh CSPRNG value per probe. The publisher accepts a `ProbeAck` only if the token
matches the outstanding probe for that session; anything else is dropped and counted. Probes occupy
no ring slot, consume no credit, and carry no sequence — which is precisely why they need their own
AM id rather than borrowing the credit path.

### 3.14 `Geometry` (128 bytes) / `GeometryAck` (32 bytes)

```text
Geometry
offset  size  field
     0    16  common prefix (msg_type 5, header_bytes 128); `generation` = the NEW epoch
    16     8  stream_id
    24     8  first_sequence   first seq that will be sent in the new epoch
    32    96  geometry         GeometryBlock (3.4)

GeometryAck
offset  size  field
     0    16  common prefix (msg_type 6, header_bytes 32); `generation` = the armed epoch
    16     8  stream_id
    24     8  first_sequence   echoed
```

Sequence numbers are monotonic **across** epochs; only the slot mapping and the window width change.
`GeometryAck` is the grant half of the interlock in §4.3.

## 4. State machines

### 4.1 Client (subscriber)

```text
Closed ──start()──► Opening ──OpenReply{Ok}──► Probing ──ProbeAck──► Active
  ▲                    │                          │                    │
  │                    │ Error / timeout          │ probe timeout      │ transport error
  │                    ▼                          ▼                    ▼
  │                 Failed ◄───── attempts exhausted ───── Reconnecting ◄──┘
  │                    │                                        │
  └────stop()──────────┴────────────────────────────────────────┘
```

| State | Entry action | Legal exits |
|---|---|---|
| `Closed` | release rings, join threads, clear callbacks' queue | `Opening` (via `start()`) |
| `Opening` | allocate + register receive ring, create worker, send `Open` | `Probing`, `Failed`, `Reconnecting` |
| `Probing` | arm ring, await `Probe`, reply `ProbeAck`, start renew timer | `Active`, `Reconnecting` |
| `Active` | dispatch frames, return credits, renew on schedule | `Reconnecting`, `Closed` |
| `Reconnecting` | drop endpoint, keep ring, back off, retry `Open` | `Opening`, `Failed`, `Closed` |
| `Failed` | terminal until `stop()`/`start()`; state callback fired with `BulkError` | `Closed` |

The frame callback fires on the dedicated Push thread and Pull callers claim frames directly;
neither delivery path runs application code on the engine thread.

Reconnect policy: `FailFast` → any transition to `Reconnecting` becomes `Failed`. `BoundedRetry` →
up to `reconnect_max_attempts` with exponential backoff from `reconnect_backoff_ms`, capped at the
last known lease TTL.

### 4.2 Server (per session)

```text
Unknown ──Open──► Open ──ProbeAck──► Armed ──first publish──► Active
                    │                  │                        │
                    │                  └────────────────────────┤
                    │                                           │
                    └──── lease deadline passed ──► Expiring ◄──┘
                                                        │
                              Close (any state) ──► Closed
```

| State | Meaning | Frames sent? |
|---|---|---|
| `Unknown` | no such `session_id` | no |
| `Open` | session allocated, ring registered, endpoint created, probe outstanding | no |
| `Armed` | `ProbeAck` received; consumer ring confirmed reachable and armed | yes |
| `Active` | at least one frame submitted | yes |
| `Expiring` | lease deadline passed; teardown in progress | no |
| `Closed` | resources released; `session_id` retired permanently | no |

**Arm-before-send is mandatory.** The publisher **MUST NOT** submit a frame to a session in `Open`.
This is the interlock that prevents landing a frame in a receive ring that is not yet registered.

Expiry is driven by a timer on the publisher's control thread, **independent of frame traffic**. A
publisher producing zero frames still expires a dead client on schedule. This is the whole point of
leases over heartbeats: Tango's ZMQ heartbeat is server→client PUB and gives the supplier no signal
that a consumer died, and the server-side subscriber decay is `EVENT_RESUBSCRIBE_PERIOD = 600 s`,
which is far too coarse to protect a pinned ring.

`Expiring` teardown order is fixed and **MUST NOT** be reordered:

1. Mark the session ineligible for new submissions (atomic flag read by the engine).
2. Wait for outstanding UCX operations on that endpoint to complete or fail (bounded wait, then
   force).
3. Close the endpoint (`ucp_ep_close_nbx`, `UCP_EP_CLOSE_FLAG_FORCE` after the bounded wait).
4. Release every producer lease still retained by this session.
5. Unregister the per-session receive-side state; unmap the ring if no lease references remain.
6. Increment `sessions_expired`, record the reason, transition to `Closed`.

Releasing leases (step 4) **before** the endpoint is closed (step 3) would hand a slot back to the
producer while the NIC may still be reading it. That ordering is the single most dangerous thing to
get wrong in this design, because the failure mode is silent payload corruption rather than an error.

### 4.3 Geometry changes

Geometry is per stream and changes through an explicit two-phase interlock:

1. Producer calls `declare_geometry(...)`. The publisher allocates and registers the **new** ring
   *in addition to* the old one, computes `generation' = generation + 1` and
   `first_sequence = next_sequence`, and sends `Geometry`.
2. The publisher keeps sending old-epoch frames from the **old** ring until `window_base` reaches
   `first_sequence` — i.e. every old-epoch frame has been credited.
3. The subscriber, on `Geometry`, allocates and arms the new ring, keeps the old one alive to drain
   in-flight frames, and replies `GeometryAck`.
4. The publisher switches to the new ring only when **both** conditions hold: `GeometryAck` for
   `generation'` received, **and** the old epoch has fully drained. It then frees the old ring.
5. The subscriber frees the old ring when the last `FrameView` from the old epoch is released.

Both sides route each frame by the `generation` in its header, so a late old-epoch frame lands in the
draining ring rather than corrupting the new one. Frames whose generation matches neither the armed
nor the draining epoch are dropped as `frames_dropped_stale_epoch`.

If `declare_geometry` cannot register the new ring, it returns `ResourceExhausted` and the stream
**keeps running on the old epoch**. A failed re-declaration is never a silent clamp to a smaller
geometry.

`RenewReply` always carries the current `GeometryBlock`, so a subscriber that missed the data-plane
`Geometry` message discovers the change within one renew interval and can re-arm.

### 4.4 Edge-case behaviour (normative)

| Situation | Required behaviour |
|---|---|
| **Duplicate `Open`, same `client_instance_id`** | A *new* session with a new `session_id` and `stream_id`. The old session is **not** reused, **not** closed, and continues to count against `max_sessions`. Clients that leak sessions hit `TooManySessions` and that is correct feedback. |
| **Duplicate `Open`, same `session_id`** | Impossible: clients never choose `session_id`. If seen, `MalformedMessage`. |
| **Duplicate `Renew`** | Both accepted (subject to the rate limit); the lease deadline is set to `now + ttl`, not extended cumulatively. |
| **Late `Renew` (within TTL, after renew interval)** | Accepted; `renewals_late++`. Not an error — one slow Tango round trip must not kill a healthy session. |
| **Late `Renew` (after expiry)** | `RenewReply{SessionExpired}`. The client MUST open a new session. No resurrection, ever. |
| **Duplicate `Close`** | `CloseReply{UnknownSession}`, no work performed, no error raised, no counter beyond a debug trace. |
| **`Close` racing expiry** | Whichever reaches `Expiring` first wins; the other observes `Closed`/`UnknownSession`. Teardown runs exactly once, guarded by a per-session atomic state CAS. |
| **Client process crash** | No `Close` arrives. The lease expires at its deadline; §4.2 teardown runs. Bounded by `lease_ttl_ms` and nothing else. |
| **Client crash, immediate restart** | New `Open` → new `session_id`/`stream_id`. Both sessions coexist until the old lease expires; both count against `max_sessions`, which is why `max_sessions` defaults above 1. |
| **Server process crash/restart** | New `server_epoch_id`. Client's `Renew` fails with a Tango exception or `UnknownSession` → `Reconnecting` → `Open`. Client MUST discard cached geometry and sequence state on a changed `server_epoch_id`. Sequences restart at 0; they are not continued across sessions. |
| **Transport error on an armed session** | Publisher marks the session `Expiring` immediately, without waiting for the lease. Subscriber transitions to `Reconnecting`. |
| **Frame for an unknown `stream_id`** | Dropped, `frames_dropped_bad_header++`. Never treated as a request to create a session. |
| **`Credit` for an unknown `stream_id`** | Dropped, `malformed_messages++`. |
| **`Credit` above highest submitted sequence** | Dropped, `malformed_messages++`, window **not** advanced. |
| **Geometry change while a session is `Open` (not yet `Armed`)** | The pending `Open` grant is superseded; the publisher sends `Geometry` as soon as the session reaches `Armed`. |
| **Geometry change during `Reconnecting`** | Resolved by reopening: `OpenReply` carries the current `GeometryBlock`, so the reconnect naturally lands on the current epoch. |

## 5. Threading and ownership

### 5.1 Thread inventory

| Thread | Count | Owns | Never does |
|---|---|---|---|
| **Application / acquisition** | N (caller's) | `BulkSource::Lease` between `try_acquire()` and `publish()` | enter UCX; take a UCX lock; block |
| **Engine** | 1 per worker/rail | the `ucp_worker` **exclusively**; all `ucp_*` calls | invoke a user callback; call Tango; allocate on the frame path |
| **Dispatch** | 1 per Push subscription | invoking `FrameCallback` | touch UCX; hold a lease longer than the callback |
| **Control** | 1 per publisher and per subscriber | lease timers, `Renew` commands, expiry sweeps, `DeviceProxy` calls | touch UCX; invoke user frame callbacks |

The `ucp_worker` is created with `UCS_THREAD_MODE_SINGLE` and is touched **only** by its engine
thread. This is not a convention to be maintained by review: the worker handle is a private member of
the engine, is never returned by any public accessor, and every cross-thread request reaches it
through a queue.

The engine loop, per iteration:

```text
1. drain publish queue        (bounded, N items max per iteration)
2. drain credit-return queue  (bounded)
3. submit eligible frames     (credit window open, session Armed)
4. ucp_worker_progress()
5. retire completions         (release header contexts; release leases on credit)
```

One tight loop that both submits and progresses — not a submit thread plus a progress thread. This is
settled by measurement, not preference: `ucx_perftest` saturates with `thread_count = 1` and a single
submit+progress loop, and the spike's `--progress-thread` variant measured ~13 vs ~16 GiB/s once the
transport bug was fixed. Scaling to two NICs means **one such loop per rail**, never a submit/progress
split.

### 5.2 The callback isolation guarantee

> User callbacks **never** run on the UCX engine thread.

Enforced three ways, in increasing order of trustworthiness:

1. **Structurally** — the engine holds no `std::function`. Its only egress is
   `delivery_queue_.try_push(...)`. There is no code path from `ucp_worker_progress()` to user code.
2. **By assertion** — the dispatch path asserts `std::this_thread::get_id() != engine_thread_id_` in
   debug builds.
3. **By test** — acceptance test A9 records the thread id inside the callback and compares it against
   the engine's, and a second test blocks inside the callback for longer than several frame periods
   and asserts that `frames_received` keeps advancing.

### 5.3 Queues and their full behaviour

| Queue | Kind | Direction | Depth | When full |
|---|---|---|---|---|
| Publish | bounded MPSC | app → engine | `publish_queue_depth` (256) | `publish()` returns `QueueFull`; **the lease stays with the caller**; `dropped_queue_full++`. Never blocks. |
| Credit-return | bounded MPSC | any → engine | `2 × ring_depth` | **Cannot fill.** At most `ring_depth` credits can be outstanding, so capacity `2 × ring_depth` makes overflow unreachable. The implementation MUST `assert` on overflow rather than handle it, because a full credit queue would deadlock the window and silently dropping a credit is unrecoverable. |
| Delivery | bounded SPSC | engine → dispatch | `delivery_queue_depth` (64) | Apply `drop_policy`. `DropNewest`: discard the arriving frame, release its slot, return its credit immediately. `DropOldest`: pop and release the oldest queued view, then push. Either way `frames_dropped_queue_full++`. **UCX progress is never stalled.** |
| Producer ring | slot pool | — | `ring_depth` | `try_acquire()` returns an empty lease; `acquire_failed++`. Never blocks — an acquisition thread must drop, not wait. |
| Receive ring | slot pool | — | `ring_depth` | Unreachable while the credit window is respected; a frame for an occupied slot is dropped as `frames_dropped_duplicate_seq`, which is a protocol violation by the peer. |

### 5.4 Producer lease lifetime — the exact rule

A producer slot is retained from `try_acquire()` until **every session it was successfully submitted
to has credited its sequence, or has been closed/expired.**

Explicitly:

- **Local UCX send completion does NOT release the slot.** Under AM rendezvous the completion tells
  you the local operation finished; the design's ownership rule is credit-based so it holds uniformly
  across AM and RMA and across the batched-flush variants under evaluation in P0-10. Send completion
  releases only the *header context* allocation.
- A lease that is destroyed without being published returns its slot immediately.
- `publish()` returning `QueueFull` does **not** consume the lease; the caller still owns it and may
  retry or drop it.
- `publish()` returning `Accepted` consumes the lease; the publisher owns the slot from then on.
- Failed submission **MUST NOT** create an uncreditable hole. Sequence assignment and window
  advancement are atomic with the engine's acceptance of the frame: a frame that fails to submit is
  never assigned a sequence, so no window gap can occur.
- On session expiry, every slot retained on behalf of that session is released as part of step 4 of
  §4.2 teardown — **after** the endpoint is closed.

### 5.5 Consumer credit lifetime — the exact rule

A credit returns when the **last `FrameView` referencing that receive slot is destroyed** (or
`reset()`), i.e. when the `shared_ptr<ReceiveSlotLease>` refcount reaches zero.

- Release may happen on **any** thread. The `ReceiveSlotLease` destructor pushes the sequence onto
  the credit-return queue; it never calls UCX directly.
- The engine coalesces released sequences into a contiguous prefix and emits at most one cumulative
  `Credit` per progress iteration.
- Out-of-order releases are tracked in a fixed-size bitmap of `ring_depth` bits. No allocation, no
  `std::set`, no data-path heap traffic.
- A view retained indefinitely withholds its credit indefinitely. That is the documented, intended
  backpressure semantic, and it is why `views_outstanding` is a counter an operator can see.

## 6. Resource defaults and limits

### 6.1 Values

All are configurable; all have a hard cap that configuration cannot exceed.

| Quantity | Default | Range | Hard cap | Constant |
|---|---|---|---|---|
| Max frame bytes | 8 MiB | 4 KiB .. 256 MiB | 256 MiB | `k_max_frame_bytes_hard_cap` |
| Producer ring depth | 32 | 2 .. 1024 | 1024 | `k_max_ring_depth` |
| Consumer ring depth | 32 | 2 .. 1024 | 1024 | `k_max_ring_depth` |
| Credit window | 16 | 1 .. ring_depth | ring_depth | — |
| Sessions per publisher | 4 | 1 .. 32 | 32 | `k_max_sessions` |
| Publish queue depth | 256 | 8 .. 8192 | 8192 | `k_max_publish_queue` |
| Delivery queue depth | 64 | 1 .. 4096 | 4096 | `k_max_delivery_queue` |
| Credit-return queue depth | 2 × ring_depth | derived | — | — |
| Lease TTL | 10 000 ms | 1 000 .. 600 000 | 600 000 | `k_max_lease_ttl_ms` |
| Renew interval | TTL / 3 | TTL/10 .. TTL/2 | — | — |
| Renewals per TTL | 10 | 2 .. 100 | 100 | `k_max_renewals_per_ttl` |
| Pinned memory per process | 1 GiB | 16 MiB .. 64 GiB | 64 GiB | `k_max_pinned_bytes` |
| UCX address blob | — | 1 .. 4096 B | 4096 | `k_max_ucx_address_bytes` |
| Drop policy (producer) | `DropNewest` | — | — | — |
| Drop policy (delivery) | `DropNewest` | `DropNewest`/`DropOldest` | — | — |

Defaults chosen so the out-of-the-box footprint is `8 MiB × 32 = 256 MiB` pinned per stream — large
enough to be useful, small enough not to trip a default `RLIMIT_MEMLOCK` accidentally.

**Pinned memory accounting.** Before any `ucp_mem_map`, the implementation computes the requested
bytes, adds them to a process-wide atomic total, and rejects with `ResourceExhausted` if the total
would exceed `pinned_memory_limit_bytes`. It **MUST** additionally read `RLIMIT_MEMLOCK` at startup
and log a warning when the configured limit exceeds it, because `ucp_mem_map` failure due to
`RLIMIT_MEMLOCK` produces a UCX status that does not name the actual cause.

**`DropOldest` is illegal on the producer ring** and `PublisherConfig::validate()` MUST reject it. A
slot already handed to UCX cannot be reclaimed; offering the option would be offering corruption.

### 6.2 Slot stride padding

`slot_stride` defaults to:

```text
stride = align_up(max_frame_bytes, 4096)
if pad_slot_stride and stride is a power of two and stride >= 256 KiB:
    stride += 4096
```

This exists because it was measured: with an exactly-1 MiB stride, all slots alias into the same
cache sets and the receive-side copy thrashes — ~5.9 GiB/s versus ~16 GiB/s once a 200-byte prefix
broke the stride. Real detector frames usually carry a prefix and are rarely exact powers of two, so
this mostly matters for benchmarks and for the unlucky detector — but a 4 KiB tax per slot to avoid a
3× throughput cliff is not a trade worth deliberating over per deployment.

### 6.3 UCX configuration

| Setting | Value | Rationale |
|---|---|---|
| Features | `UCP_FEATURE_AM` (plus `UCP_FEATURE_RMA` only if `transport_selected == 2`) | AM rendezvous is the baseline |
| Thread mode | `UCS_THREAD_MODE_SINGLE` | one engine thread owns the worker |
| Endpoint error mode | `UCP_ERR_HANDLING_MODE_NONE` by default | `PEER` excludes every transport without a peer-failure handler — the cause of the "10× problem" that turned out to be tcp/lo fallback. Session leases provide liveness, so `PEER` buys nothing on the critical path. |
| `UCX_TLS` | unset by default | tests pin it via `ucx_tls`; production lets UCX choose |
| Ring allocation | `UCP_MEM_MAP_ALLOCATE` where the ring is library-owned; `UCP_MEM_MAP_PARAM_FIELD_ADDRESS` when adopting a vendor ring | vendor rings are the normal detector case, not an optional convenience |

`UCP_ERR_HANDLING_MODE_PEER` MAY be requested via configuration on hardware where `rc`/`dc` implement
it, but it **MUST NOT** be the default, and the configuration MUST document that it changes transport
selection.

## 7. Tango integration contract

### 7.1 Commands

| Command | Signature | Level | Idempotent |
|---|---|---|---|
| `BulkOpen` | `DevVarCharArray → DevVarCharArray` | `Tango::EXPERT` | no — each call creates a session |
| `BulkRenew` | `DevVarCharArray → DevVarCharArray` | `Tango::EXPERT` | yes |
| `BulkClose` | `DevVarCharArray → DevVarCharArray` | `Tango::EXPERT` | yes |
| `BulkStreams` | `DevVarCharArray → DevVarCharArray` | `Tango::OPERATOR` | yes |

All three take an encoded coordination message (§3.3) and return an encoded reply. `DevVarCharArray`
is used rather than `DevString` because the payload is binary and must not be subject to encoding or
NUL-termination semantics.

A command **MUST NOT** throw `DevFailed` for a protocol-level failure. Protocol failures are returned
as an encoded `Error` message with a `Status`. `DevFailed` is reserved for conditions the extension
did not model — the command never even reached `handle_coordination`. This keeps the client's error
handling in one place instead of split across two mechanisms.

### 7.2 Registration helper

```cpp
namespace TangoBulk {

struct CommandNames
{
    std::string open{"BulkOpen"};
    std::string renew{"BulkRenew"};
    std::string close{"BulkClose"};

    static CommandNames with_prefix(const std::string &prefix);  // "Xyz" -> "XyzBulkOpen"
};

// Called from DeviceClass::command_factory(). Appends three commands that
// dispatch to the BulkPublisher attached to the receiving device.
void install_bulk_commands(Tango::DeviceClass &device_class,
                           const CommandNames &names = {});

// Called from DeviceImpl::init_device(). Binds `publisher` to `device` so the
// installed commands can find it. Detach on delete_device().
void attach_publisher(Tango::DeviceImpl &device, BulkPublisher &publisher);
void detach_publisher(Tango::DeviceImpl &device) noexcept;

} // namespace TangoBulk
```

Device integration is therefore three lines: `install_bulk_commands(*this)` in `command_factory()`,
`attach_publisher(*this, *publisher_)` in `init_device()`, `detach_publisher(*this)` in
`delete_device()`.

A command invoked on a device with no attached publisher returns `Error{UnknownStream}` rather than
throwing. A device server that has not finished `init_device()` is a normal transient state, not a
fault.

### 7.3 Authorization expectations

**The extension is not a security boundary and MUST NOT be described as one.**

- Authorization is the device server's existing Tango policy. `BulkOpen`/`BulkRenew`/`BulkClose` are
  ordinary commands and are subject to whatever Tango access control the facility already applies to
  write-level commands. The extension performs no authentication of its own.
- `BulkOpen` and `BulkClose` MUST be treated by integrators as **write-level** operations: `BulkOpen`
  causes pinned-memory allocation and `BulkClose` terminates a data stream. Registering them at
  operator level where Tango access control distinguishes read from write is a misconfiguration, and
  the documentation MUST say so.
- - The UCX data plane itself is **unauthenticated and unencrypted**. A client that obtains a valid
  `stream_id` can send credits for that stream. This is acceptable only on a trusted facility network,
  and §3.12's "credit above highest submitted sequence" check is a robustness measure, not a
  security control. Encryption and authenticated endpoints require an explicit threat model that this
  document does not attempt.
- Resource limits (§6.1) apply per publisher regardless of the caller's identity, so an authorized
  but buggy client cannot exhaust the server.

### 7.4 How the client adapter uses `DeviceProxy`

```cpp
Tango::DeviceProxy proxy(device_name);
TangoBulk::SubscriberConfig cfg;
cfg.stream_name = "image";

TangoBulk::BulkSubscriber sub(proxy, cfg);
sub.set_frame_callback([](TangoBulk::FrameView f) { process(f); });
sub.set_state_callback([](auto state, const auto &err) { log(state, err); });
sub.start();
```

Contract:

- The proxy is **borrowed**, never copied, never owned. The caller guarantees it outlives the
  subscriber. `stop()` (and the destructor) complete all proxy use before returning.
- Only the **control thread** calls the proxy. The engine thread and the dispatch thread never touch
  Tango. This means the subscriber never blocks UCX progress on a Tango round trip, and a stuck Tango
  call cannot stall frame delivery — it can only, eventually, expire the lease.
- The adapter scopes `set_timeout_millis(command_timeout_ms)` around each call and restores the
  caller's previous timeout afterwards, so the application's proxy configuration is not mutated.
- The adapter calls only `command_inout`, `set_timeout_millis`, `get_timeout_millis`, `name`, and
  `status`. It does **not** call `subscribe_event`, does not register callbacks, and does not create
  a second connection.
- A `DevFailed` from `command_inout` is a **recovery hint**, not cleanup authority. It moves the
  subscriber toward `Reconnecting`; it never releases publisher-side resources. Only the lease does
  that.

### 7.5 Preview attribute — separate by construction

`examples/example_preview/` demonstrates the compatibility path and MUST remain a *separate* code
path from the bulk publisher:

```cpp
// In the device, decimated and rate-capped. NOT on the bulk path.
if(preview_throttle_.due())
{
    downsample(bulk_lease.data(), preview_buffer_);   // explicit copy, small
    preview_attr_.set_value(preview_buffer_.data(), preview_w_, preview_h_);
    push_change_event("preview");
}
```

Constraints the example MUST demonstrate:

- The preview attribute is an ordinary Tango image attribute with an ordinary change event.
- Its rate is capped (default ≤ 10 Hz) and is independent of the frame rate.
- It never carries data required to interpret a bulk frame — a bulk frame is self-contained.
- The bulk path itself constructs **no** `AttributeValue_5` and calls **no** `push_change_event()`.
  Acceptance test A10 asserts this by counting events emitted during a bulk-only run: the expected
  count is the preview rate, not the frame rate.

## 9. First implementation slice

### 9.1 M0 — repository scaffold

Exit criteria:

1. `tango-bulk` configures and builds with `find_package(Tango)` resolving to an **installed**
   package; the configure step fails if it resolves into a source or build tree.
2. Four library targets exist with the §1.1 dependency rules enforced by a CI include-grep.
3. An empty Catch2 executable runs.
4. `REV` of the cppTango prototype is recorded in `docs/EXTRACTION.md` along with this map.
5. LGPL notices preserved on every extracted file; provenance recorded per file.

No behaviour. This milestone is about the boundary being real.

### 9.2 M1 — protocol core

Pure `src/core/`, no UCX, no Tango, no threads.

- Every message in §3, encode and decode, with the exact byte layouts.
- Bounds validation per §3.4 and §3.9.
- CSPRNG session/stream identifiers.
- Credit window with the bitmap.
- Geometry validation.

Tests (`tests/unit/`), all runnable in milliseconds with no external resources:

| Test | Asserts |
|---|---|
| Round trip, every message type | encode → decode → field-by-field equality |
| Golden vectors | a committed hex blob per message type decodes to known values — this is what catches an accidental layout change in review |
| Truncation sweep | for each message, decoding at every length from 0 to `len-1` returns `MalformedMessage` and reads no out-of-bounds byte (verified under ASan) |
| Corruption sweep | flipping each bit of the fixed part either decodes to a valid-but-different message or is rejected; never a read overrun |
| Version rules | wrong major rejected; larger `header_bytes` accepted with trailing ignored; smaller than minimum rejected |
| Bounds | oversize `max_frame_bytes`, `rank > 4`, nonzero shape beyond rank, overflowing `shape × element_size`, oversize strings/blobs all rejected |
| Endianness | encoded bytes match the spec's offsets literally, asserted against hand-written expected arrays, so the test fails on a big-endian host rather than passing vacuously |
| Credit window | cumulative advance, duplicate/reordered credits, out-of-order release, ack above submitted rejected |

Exit: the golden vectors in this document and the implementation agree.

### 9.3 M2 — the minimal vertical slice

This is the slice that must be built first, and it is deliberately small:

```text
registered producer lease
    → dedicated UCX engine
    → self-contained frame
    → registered consumer slot
    → FrameView
    → credit on release
```

**In scope:** one publisher, one subscriber, both in the same test process on a UCX loopback
transport; one registered producer ring; one engine thread; the `Frame` and `Credit` messages; one
registered receive ring; `FrameView` with the shared-ptr lease; cumulative credit on release.

**Explicitly out of scope for M2** — none of these may be added to make a test pass:

- no Tango process, no `DeviceProxy`, no commands (the coordination plane is driven directly through
  `handle_coordination`, or by `oob.hpp` in the UCX tests);
- no user callbacks and no dispatch thread — `DeliveryMode::Pull` reads only;
- no geometry changes;
- no probe;
- no session leases, renewal, or expiry;
- no reconnect;
- no relay;
- no RMA.

Exit criteria — the slice is done when these pass:

| Test | Asserts |
|---|---|
| Single frame | bytes arrive intact; `FrameView` fields match the published `FrameMetadata` |
| Zero copy | the payload address delivered to the callback lies inside the registered receive ring, and no copy of payload size occurs — verified by pointer/registration instrumentation, not by inspection |
| Wraparound | publishing `4 × ring_depth` frames reuses every slot correctly; slot `i` holds sequence `s` iff `s % ring_depth == i` |
| Lifetime under retention | holding a `FrameView` withholds exactly one credit; the publisher stalls at `credit_window` outstanding and resumes when the view is released |
| Out-of-order release | releasing views out of order advances `ack_sequence` only across the contiguous prefix |
| Credit exhaustion | with all views retained, `publish()` returns `CreditStalled` and `dropped_credit_stalled` increments; nothing blocks; no slot is reused |
| Lease return | `publish()` on a full publish queue returns `QueueFull` **and the caller still holds a usable lease** |
| ASan/UBSan clean | the whole suite under sanitizers, including teardown with views still outstanding |

Only once M2 passes lifetime and wraparound do we add, in this order: **session leases** (M3), then
the **stock-Tango command adapter** (M4).

### 9.4 Concurrent hardware track

Independent of M0–M2 and starting immediately, `experiments/ucx-bulk-spike/` runs on target RDMA
hardware, unchanged. Priority order:

1. **P0-10 — flush amortization** (K = 1, 4, 16, 64 at 1/2/4/8 MiB). This is first because it is the
   one open result that could still move the frame-ownership contract §5.4 fixes. If batched flush is
   required to reach line rate, the credit/completion coupling must be re-examined **before** M2
   hardens it — which is exactly why the tracks run in parallel rather than in sequence.
2. **P0-1 / P0-7 / P0-8** — AM vs RMA, latency, and the pinned-memory ceiling on real hardware.
3. **P0-11** — one engine per rail, CPU affinity, NUMA placement.
4. **P0-12** — `ucp_worker_fence` vs flush ordering.
5. **P0-14** — whether `UCP_ERR_HANDLING_MODE_PEER` changes `rc`/`dc` selection or performance.

Blocking prerequisite carried over from [FINDINGS.md](FINDINGS.md): **the RMA path must get a
receiver-side slot checksum plus a negative control (flush removed ⇒ checksums fail) before any RMA
number is used to justify a decision.** A missing flush shows up as a *faster* result, which is the
one failure mode that argues for shipping the broken thing.

Results land in [THROUGHPUT.md](THROUGHPUT.md) as reproducible command lines, machine/NIC/UCX
configuration, raw output, and a conclusion.

## 10. What this document does not settle

Recorded so the gaps are visible rather than discovered:

- **Batched-flush effect on ownership.** §5.4 assumes credit-based release is sufficient under
  batching. P0-10 confirms or refutes it. If refuted, §5.4 changes before M2 hardens.
- **Two-rail engine partitioning.** §5.1 says one engine per rail; how a stream is assigned to a rail
  (static, round-robin, NUMA-derived) is deferred to M5 with hardware in hand.
- **Relay protocol.** M6. The relay is a subscriber and a publisher back to back; whether it
  re-registers or forwards registered memory is a measurement, not a design choice to make now.
- **Python bindings.** Post-MVP, copy-only. Zero-copy NumPy lifetime semantics need their own design.
- **GPU memory.** `MemoryKind::Cuda`/`Rocm` appear in the protocol so the field is not retrofitted
  later. No implementation in the MVP.
- **Encryption / authenticated endpoints.** Requires a threat model (§7.3).
