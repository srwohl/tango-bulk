Can the five changes deepen what is already here?

This throwaway logic prototype answers one design question: can the five proposed issues be expressed by deepening the existing Subscription, ReceivePlan, PinnedBudget, DeliveryQueue, BulkPublisher, and Tango adapter, without creating a new top-level “Establishment” module?

Watch for this: the public journey should be one Subscription owning the order of discovery, planning, Open, delivery, reconnect, and close. Typed values and adapters may appear at the seams; a second orchestration object should not.

Guided walkthroughs

Ownership after deepening

SubscriptionOwns establishment order, immutable delivery mode, session generation, reconnect, and terminal outcome.
ReceivePlan + PinnedBudgetTurn a StreamOffer and a budget into one reserved, validated receive plan.
DeliveryQueueOwns the one authoritative queue, wakeup, acceptance ordering, and consumer-facing drain.
BulkPublisherOwns typed coordination behavior and the authoritative stream snapshot.
Tango adapterTranslates attributes and encoded commands; it does not own stream state or policy.
